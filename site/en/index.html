Historical mind map preservation

Recover, browse, and preserve your historical MindMup 2 mind maps.

MindMup 2 Conversor turns compatible .mup files into normalized JSON-CMJN and self-contained HTML. The aim is to recover the information from maps you no longer use every day, browse it comfortably, and preserve it outside the MindMup interface.

Context

What MindMup is and why its maps are worth preserving.

MindMup is a web application for creating mind maps and organizing ideas through nodes and hierarchical relationships. Its official website also covers organization charts, fishbone diagrams, argument visualization, notes, attachments, publishing, and Google Drive storage. You can find out more about the product on the official MindMup website.

MindMup 2 and MindMup 3

A transition that preserves maps, teams, and settings.

The official documentation announces that MindMup 3 gradually replaces MindMup 2 from 13 April. According to that same documentation, maps are migrated automatically, teams and members are preserved, and account settings and history remain. Some classic features change: Measures, Progress, and Storyboards are not carried over to MindMup 3, and Fishbone maps become read-only.

During the preview, existing maps appear in MindMup 3 as read-only; editing existing maps remains in MindMup 2 until the migration.

Access and editing

Reading is not the same as editing.

From 1 June 2026, MindMup for Google Drive becomes a paid product and requires a Personal subscription or higher. Free accounts can no longer create or edit maps with that application; existing maps remain accessible, but editing them requires a paid subscription. The official documentation recommended that anyone who did not plan to upgrade export and save important maps before that date.

The official documentation states that, from 6 October, the Starter plan includes up to 3 editable maps instead of 5. Maps over the limit become read-only and remain available to open and browse; existing maps are not deleted. The limit applies only to Starter accounts: Personal, Team, and Organization retain unlimited editable maps.

Reading, editing, importing, migrating, and exporting are different operations. A restriction on editing does not prevent you from browsing the map or keeping a copy of its information. This converter does not import maps into MindMup: it processes a .mup file that you have already exported.

The problem

The map exists, but recovering its information is not always immediate.

Maps accumulate years of notes, relationships, and decisions. When the version, plan, or access conditions change, keeping the file is not enough: you need to be able to read it, browse it, and preserve it independently of the original interface.

Information that remains

Years of work inside a file.

Each node can contain notes, attributes, references, and resources. That information retains its value beyond the original editing session and deserves a stable, understandable, and easy-to-preserve way to browse it.

Dependence on the application

Access changes; the content still matters.

Reading, editing, importing, migrating, and exporting are not the same operation. An editing restriction can make everyday use harder, but it does not automatically make the map unreadable.

The aim is not to replace MindMup, but to recover the content and preserve it in a format that can be browsed and downloaded.

The solution

A way to recover the content and preserve it outside the application.

MindMup 2 Conversor processes compatible .mup files, extracts the map information, and generates normalized JSON-CMJN and self-contained HTML. The result can be browsed, downloaded, and preserved regardless of whether the conversion service remains available.

JSON-CMJN: ten collections for browsing the information

The JSON is generated after the map has been extracted and normalized. It brings the information together in these collections:

  • metadataIdentity, version, source file, and node count.
  • nodesFlattened nodes with hierarchy, depth, path, and sibling order.
  • notesNotes associated with nodes.
  • attributesAttributes and styles.
  • stickersStickers and emojis.
  • iconsIcons, including those embedded as data:.
  • linksInternal links between nodes.
  • externalRefsClassified external references.
  • enumsEnumerated values.
  • indexesPrecomputed indexes.

How it works

From a .mup file to a result you can preserve.

Compatibility is checked against the file's formatVersion. The process is the same in all three variants; what changes is where it runs and which output is offered.

  1. 1

    Step 1: Export the map

    Save the map from MindMup as a .mup file. Check that it declares formatVersion: 3 before uploading it. The web variants validate the extension, size, JSON, and required fields; the local converter validates the JSON and the fields.

  2. 2

    Step 2: Convert the structure

    Eight layers read the map, flatten the tree, extract notes, separate attributes, convert stickers, classify references, assemble the collections, and save the result.

  3. 3

    Step 3: Get the JSON-CMJN

    The result is a normalized JSON with ten collections. It includes the node hierarchy, notes, attributes, resources, and computed indexes.

  4. 4

    Step 4: Open or download the result

    The visualizer builds a self-contained HTML file. The public variant lets you preview it and download it as a ZIP; the variant with login adds JSON download; the local converter writes the JSON and, with the corresponding option, the HTML to a folder.

Compatibility: the converter accepts .mup files with formatVersion: 3 and rejects those that declare formatVersion: 2. It does not read or validate the commercial version of MindMup.

The eight conversion layers

Conversion process layers
Layer What it does
1. Reading Interprets the .mup file and extracts the map metadata.
2. Flattening Traverses the tree and creates one node per idea with parent_id, depth, path, and sibling_order.
3. Notes Extracts the note text and associated data.
4. Attributes Separates node styles, positions, and attributes.
5. Stickers Converts emoji codes into entries in the stickers collection.
6. References Finds and classifies external addresses.
7. Assembly Brings together the ten collections with source_file, converted_at, and node_count already calculated.
8. Storage Writes the JSON to R2; the local converter saves it to the output folder.

The HTML includes tree navigation, a visible node counter, expand and collapse, theme switching, notes, stickers, icons, references, links, attachments, a node index, and breadcrumb navigation.

Technical information

Compatibility, versions, and retention.

Compatibility is determined by the file's internal formatVersion, not by MindMup's commercial name. This distinction avoids confusing the application version with the file format version.

What it accepts

Files with formatVersion: 3.

The converter accepts .mup files whose formatVersion is 3. Files with formatVersion: 2 are rejected; if the file has another value, it is not supported either.

The converter does not read or validate the commercial version of the MindMup application. The official documentation does not document the internal formatVersion value of .mup files.

What has not been demonstrated

No universal compatibility has been demonstrated.

It has not been possible to demonstrate that all files exported by MindMup 2 use formatVersion: 3, or that all files exported by MindMup 3 use another value. Check your file's formatVersion before assuming the converter will accept it.

Compatibility note: the converter accepts .mup with formatVersion: 3; it rejects formatVersion: 2; it does not read the commercial version of MindMup; and it has not been demonstrated that all MindMup 2 files use formatVersion: 3.
